## Shared upload contract (locked)
POST /api/mail-insights/snapshot with Authorization: Bearer <Supabase access token>. No cookie or ID-only upload fallback. Derive owner from verified token and reject mismatched payload.client_id. Caller must be an active approved client. GET /api/mail-insights/config is public and returns {supabase_url, publishable_key, app_url}; no secret credentials. GET /api/mail-insights/connection requires bearer and returns {client_id,workspace_id,display_name,email,last_revision}. SDK on local backend signs into Supabase with email/password, refreshes session, never stores password.

Snapshot JSON (strict fields): {schema_version:1,client_id:UUID,revision:positive safe integer,generated_at:UTC ISO timestamp,timezone:"America/Chicago",mailboxes:[{email:string,account_label:string,collected_at:UTC ISO|null,coverage_start:"YYYY-MM-DD"|null,rows:[{date:"YYYY-MM-DD",category:string,handled:boolean,action_required:boolean,retryable:boolean,count:nonnegative integer}]}]}. Normalize email trim/lower, never strip dots/plus. All 10 category IDs from mail-check taxonomy. At most 2 MiB, unique normalized mailboxes and cube keys. No message content or IDs. Identical retries no-op, old/conflicting revision 409 {error,code:"revision_conflict",last_revision}; successful {ok:true,revision,received_at,unchanged:boolean}. Preserve last revision/original hash separately from prunable data. Max one bounded conflict rebuild retry from CURRENT database; never rebase old pending payload. Single client per installation; client switches pause syncing and never retarget pending data.

## Local API contract (locked)
GET /api/bidder-check/status -> {connected:boolean,enabled:boolean,client_id:string|null,display_name:string|null,email:string|null,app_url:string,last_uploaded_at:string|null,error:string|null,duplicate_mailboxes:string[],accounts:[{id:number,label:string,email:string,selected:boolean}]}.
POST /api/bidder-check/login {app_url:string,email:string,password:string} -> same status. Authenticate+validate client, sync initially disabled.
POST /api/bidder-check/settings {enabled:boolean,account_ids:number[]} -> status; one selected source per normalized mailbox, duplicates rejected.
POST /api/bidder-check/sync {} -> status (queue current snapshot, background network).
POST /api/bidder-check/logout {} -> status. Revoke only local auth session, clear keyring, pause sync; preserve local mail and saved cloud metrics.
Local frontend never sees tokens. Backend origin/desktop protections remain. SDK refresh under crossprocess lock, keyring persistence for complete session, transient network errors do not clear tokens, explicit revoked refresh pauses sync. Poll dirty SQLite state on independent worker every <=60s; no frontend-tab dependency. Existing local dashboard predicates preserved including latest-classification JOIN and category-tier attention semantics. Track successful collection per account going forward; unknown legacy coverage null. Duplicate local mailbox sources must be explicitly selected once. Save queue/revision atomically in SQLite before send. Failed export is not an authoritative empty roster.

## Cloud read/UI contract (locked)
GET /api/mail-insights/report?from=YYYY-MM-DD&to=YYYY-MM-DD&workspace=UUID&bidder=UUID&profile=UUID&email=... (all query fields optional; valid cookie auth required, optionally bearer). Returns {mailboxes:[{email,account_label,collected_at,coverage_start,rows}],assignments:[{id,workspace_id,bidder_id,bidder_name,profile_id,profile_label,email,archived}],bid_rows:[{date,workspace_id,bidder_id,profile_id,assignment_id,email,found,applied}],received_at:string|null,generated_at:string|null,range:{from,to,clipped:boolean},status:"ready"|"not_synced"}. RPC must project caller-authorized mailboxes and assignments before returning; bidder only their active assignments+active profile, client own workspace, admin existing manager permissions. Limit range to requested interval intersect rolling 90 CT days, mark clipped; no overlap returns rows empty with clipped and valid requested range, no fabricated coverage. Existing original bid report long ranges unchanged. New table bid_rows uses ONLY found and applied_activity events, daily counts; preserve current-assignment email grouping. Shared mailbox counts dedup within each group and global totals; shared rows labeled, never claim bid matching/conversion. Client sees uploaded unassigned mailbox labeled Unassigned; bidders never do. Missing mail snapshot assigned email shows bid counts + Not synced. Full raw JSON blob never returned to bidders.

UI in src/components/dashboard.tsx after existing Application activity chart and before comparisons. Existing four mail cards, stacked category chart, all category totals (application_ack label Confirmation emails). Combined table tabs Email default/Profile/Bidder(manager only), Found,Applied activity,Confirmations,Interview emails,Assessments,Offers,Rejections. All original comparisons remain. Existing This week default applies. Common date/bidder/profile/workspace/email filter shared with new report; mail category/status/action filters affect only mail counts. Independent error state keeps existing bid report usable. No message explorer. Show coverage/freshness and current assignment label, no conversion rate. Mail row selection should filter bid report too; extend ReportQuery.email as needed safely.
